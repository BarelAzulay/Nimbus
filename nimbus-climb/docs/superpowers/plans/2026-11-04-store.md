> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One money path for Nimbus Climb: a full-size Robux `Store` window (packs, passes, potions, Tokens and Gems), a 7-day streak and per-day play-time gifts behind one Gifts button, a Sky Trove chest in the lobby that pays once for a verified group join, and one `Multipliers` module at the five earning sites, with every grant server-side, idempotent across retries, rejoins and two servers, and the economy sims green with every paid multiplier on.

## Review Focus

1. A purchase receipt that arrives while the buyer is in a match (`InMatch`): `StoreRequest` is refused in a match, but Roblox may deliver the receipt of an earlier prompt then; it must be granted, never pended for the match — `store_router` case "late receipt in a match" (Task 9).
2. A Starter Pack receipt whose pet, Cash and potion all land, then the SAVE fails and the player leaves: the orphan retry must save pet, Cash, potion and `Bought.Starter` together, and a rejoin on another server before that retry must end with ONE pet copy, +1000 Cash once, one potion hour, `Bought.Starter` once — `p7data_store_merge` (Task 5).
3. A daily claim exactly at the boundary: `now - LastClaimAt == ReadySeconds` is ready and `== KeepSeconds` is still kept (no step-back); a stored `LastClaimAt` more than `FutureClockSlack` (300 s) in the future (a server with a wrong clock wrote it, or this server's clock runs behind) is clamped: it counts as the now of its first sight (the join's payload, or a claim, which is then refused ONCE with `Next gift in 20h 0m`), so the player is never locked out for hours; LastClaimAt is never written (re-review round 1: a written clamp let a server whose clock runs behind pull the stored claim earlier for every other server), the first sight is noted next to it (`Daily.ClampFrom` / `ClampAt`, re-review round 2) and counts on every later session of a server whose clock also sees the stamp ahead, never on one that sees it as past (the accepted cost: spec Z8) — `fixr_daily_clamp_rejoin`, `daily_claim` case "boundaries" (the clock written directly with `MutateDaily`, the claim fired WITHOUT advancing first: the mock's `os.time()` is `floor(EPOCH + Clock.now)`, so an advance between the write and the fire can add a second and turn a 48 h gap into a step-back) and `daily_future_clock` (Task 10).
4. The play tick when the character is dead, despawned or has no `HumanoidRootPart` (between respawns): no error, no seconds added, no `PlayStart` reset; and a tick that crosses the 20 h play-day while a tier is claimable loses that tier without paying it (Q17) — `daily_playday` case "no root" (Task 10).
5. The Trove prompt pressed twice within the cooldown and from two servers at once by the same player: ONE `IsInGroupAsync` call PER SERVER VISIT is the real guarantee (`trove_exploits`: 20 Joined in a second = at most one call; `trove_stale_once`: a second Joined after a false answer makes no call), one grant in the store, the second server's late save adds nothing (union + the twin rule) — `trove_two_servers` (Task 6: server B is driven through its own DataService copy's `MarkTrove` + `AddCash` + `AddTokens`; there is no seam for a second TroveService, and the test says so) and `p7data_trove_merge` (Task 5).
