# Attack effects: bigger, more, growing with evolution — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every pet attack is bigger (Common x1.3 .. Secret x1.6, x1.15 / x1.3 more per evolution), every hit at every rarity gets a shockwave ring, a flash, sparks and a ground mark plus a short camera kick on your own attacks, scorch marks / embers / fading zones hang on up to 2 s longer while clearly reading as over, and an evolved pet's abilities REALLY reach farther on the server (x1.15 / x1.3), drawn exactly as they hit, with the 2026-10-31 balance intact.

**Architecture:** Four tasks on branch `attack-fx` (worktree `Projects Main\Nimbus\.worktrees\attack-fx\nimbus-climb`), in order. Task 1 is the gameplay change: one reach table + one function in `BattleCatalog`, one stage reader + one reach reader in `BattleSim`, the real numbers riding on the `Special` / `Element` / `Zone` events, the client drawing those numbers, the Pets detail line, a sim target. Tasks 2 and 3 are data in `AttackFxCatalog` plus small, flagged behaviours in the `AttackFx` engine (`Reach`, `Linger`, `CloudSize`, the kick); `BattleController` only forwards event numbers and gains a tail on the pet Storm zone. Task 4 is the full balance run and the docs. Every check runs through `py -3.12 tools/smoke.py --quick --only ...`, `tools/sim_battle.lua` under lupa and `node tools/check.mjs`.

**Tech Stack:** Roblox Luau written as plain Lua 5.1 (the repo rule), Rojo layout under `src/`, Python 3.12 + lupa for the mock world (`tools/robloxmock.lua`), `tools/contract.json` + `tools/check.mjs` for the module API contract.
